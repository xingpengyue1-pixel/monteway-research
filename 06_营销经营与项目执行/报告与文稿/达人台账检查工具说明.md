# 达人台账检查工具说明

2026-10-27｜本地Python工具，使用标准库，不联网、不安装依赖、不读取身份证、不写回原始台账。

## 它解决什么问题
检查一人多账号、重复自然人ID、跨人重复账号、缺准入和承接依据、无效或过期合作、员工排除、截止日存续确认及活动日期。输出的是「形式条件满足人数」，不是身份或证据真实性认证，也不是自动业务验收。

本轮已用22项模拟案例测试；所有模拟对象均以「演练」标识，仅在测试代码中生成，未写入真实主表。读取前轮实际空主表的结果为「尚无业务数据」，人数保留未知；不能解释为已证实零合作或目标失败。

## 表格怎么填
使用[验收扩展主表](工具/达人主表_验收扩展.csv)另存运行版本；前轮16列原名不变，新增5列：合作对象类型、是否内部员工、自然人去重依据、准入通过日、承接确认日。旧台账有业务数据后可映射复制，不能只按文件行数统计。

- 自然人内部ID：由负责身份核验的一方分配，一人一个稳定ID；多个账号以分号分隔，建议「平台:账号」。昵称相同不等于同人，不同账号也不等于不同人。
- 合作对象类型：目标范围填「自然人达人」。机构、员工或采购客户不能为了计数改类型；是否内部员工须明确「是／否」，未知不计入候选。
- 准入状态：通过后填「通过」，并记录准入日期和证据。合作确认、承接记录、责任人及日期分别保留，文字占位如「待核」不能通过。
- 当前关系状态：可计入的状态为「有效」或「有效合作」。如果只是暂停排期但合作仍有效，须业务核实后填有效并备注；工具不会猜测暂停含义。
- 合作有效至：填写真实YYYY-MM-DD；合同为持续有效时填写「持续有效」，同时有合作依据和本次截至日存续复核。截止日当天到期按当日仍有效处理，具体时点存在争议时先由业务澄清。
- 最后复核日：本工具采用本次截至日已确认存续的快照口径，须与命令截至日相同。这是本轮验收工具的管理约定，不是额外法律规定；日常旧快照不能直接倒推D90。
- 首次发布、真实净订单与活跃日期可以空缺，不因此把已有效合作剔除。但空缺不能当未出单或未活跃的实绩结论，工具只报告日期字段完整的数量。

所有日期使用YYYY-MM-DD。准入证据、合作依据、承接记录及去重依据填内部记录编号或路径；工具不自动打开附件。业务复核须核验实际文件、人员与账号的对应关系，防止不同ID其实属于同一人。重复ID和跨人重复账号的冲突行全部进入待核，不任意保留一行。

## 运行方法
在本交付目录打开终端，使用实际截止日运行，下例路径与日期需按真实情况调整：

```bash
python3 工具/check_creators.py \
  --input 工具/达人主表_验收扩展.csv \
  --as-of 2026-10-27 \
  --output 核对记录/达人结构检查_新版本.json
```

D1确认后可以增加`--start YYYY-MM-DD`，工具用D1加89天得到D90，明确此次是否D90快照。没有D1仍能检查当前台账，但不会声称已做D90验收。输出文件已存在时工具拒绝覆盖，请用新版本文件名；原始CSV始终不改。

重新验证工具：

```bash
python3 工具/test_creators.py
```

## 如何办理结果
先处理逐行问题并核实际依据，再由业务复核人员确认自然人唯一性、合作真实性与截止日有效性。即便形式条件达到100，也不能跳过真实证据核验；没有D90快照尤其不能宣布目标完成。最近28天活跃使用前轮拟议管理口径，与有效合作人数分开。

本版本只查主表快照，不自动回放状态事件。退出和恢复沿用原ID，在原事件表记录；PMO另核「期初＋新增有效（含恢复）−失效」与主表快照的差异，不能把恢复计成新自然人。推广收入、净订单和售后真实性不在此工具的自动核验范围。

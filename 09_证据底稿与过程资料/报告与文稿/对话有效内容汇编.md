## 三 已确认口径与尚待证明的事项

### 1 产品现状与业务边界

本对话沿用用户于2026年10月27日确认的现状：目前只有乳清原料，成品需开发。后续如有有效新证据，可标明日期和依据后更新；不得从旧包装或招商材料推定已有可售SKU。

A线为乳清原料线上获客、应用沟通及企业客户拓展；B线为成品开发协同、内容与渠道及达人筹备，具备条件后开展经营试点。两条线的对象、成交过程、能力与资金需求不同，不能使用同一套招商逻辑或统计口径。

历史分工为蒙特威承担原料研发生产及成品生产包装，潜势承担产品设计、定位与全国线上招商推广。具体承制主体、开发管理责任、费用、成果权属与商业条件仍需明确。营销负责人主导市场需求、获客、内容、商务和经营复盘，协调产品开发与交付；技术质量、生产放行、合同和财务审批由相应责任主体承担。

### 2 目标和计数口径

保留“90天有效合作达人不少于100人”目标，产品开发期计入同一90天。目标本身不证明可达性，现有资料尚不足以给出达标概率。不得通过放宽有效合作定义使目标看起来已经完成。

有效合作按自然人去重，需有适用准入、真实合作确认及有效期、具体可追溯的服务承接，以及截止日仍有效的证据。意向、入群、候补名单和空协议不能直接计数；一人多账号不能重复累计，原料采购客户不计入达人目标。开发期真实合作可依原定义核验，但不等于产品已可售、已经排播或已经出单。有效人数、活跃、出单和经营收益分别报告。

真实启动日D1须有依据，文件编制日不自动成为D1；已启动时不能为重新编制材料而重置时钟。期初有效人数N0尚无依据时标记待核，不按零值处理。阶段数量不能仅把100人平均拆分，应由实际起点、转化、存续及服务容量支持。

### 3 资料缺口与核读限制

在本对话核读的主链中，原料牌号及对应COA、供货参数、同条件承制报价、批准预算、实名负责人和可投入工时、真实D1及N0仍未全部落实。这里的“未取得”不推定企业内部没有资料。

## 四 深入研究前必须回答的四个问题

本对话将深入程度的判断标准明确为：经营判断如何得出、启动条件如何验证、结果由谁验收。以下保留四点分析的完整有效内容；这些是研究与核验方法，不代表相应核查或外部动作已经完成。

### 1 顶尖专家会主动做哪些没有被明确要求的动作？

他们会先检查项目是否具备启动条件，并找出最值得优先验证的业务路径。

| 主动补做的动作 | 要解决的问题 | 应形成的成果 |
|---|---|---|
| 核实企业实际可供给的产品 | 「有乳清原料」具体意味着什么：什么牌号、什么规格、适用于什么场景、能否稳定供货？ | 原料产品事实卡、供货条件表、证据缺口 |
| 重新划分原料与成品两条业务线 | 两条线的客户、成交周期、人员能力和资金需求不同，不能共用一套招商逻辑 | 两条业务路径及资源分配建议 |
| 检查目标是否与业务价值一致 | 「90天有效合作达人不少于100人」怎样带来实际经营价值？与原料客户开发如何对应？ | 目标关系图、计数规则、资源条件与偏差处理 |
| 找到启动阶段最主要的制约因素 | 当前最缺的是产品证据、应用能力、客户需求、承制资源、负责人，还是资金？ | 关键制约因素及优先解决顺序 |
| 从客户采购流程反推营销安排 | 客户为什么换用蒙特威原料？谁提需求、谁试样、谁批准采购、谁承担风险？ | 客户决策链与销售推进流程 |
| 从实际工作量反推团队 | 不先拍定人数，而是计算获客、沟通、技术转接、内容审核和合作维护需要多少工时 | 最小团队配置与扩编触发条件 |
| 设计可能推翻方案的验证 | 哪些证据出现，就说明当前产品方向、渠道或合作方式不值得继续投入？ | 验证任务、继续条件、调整或暂停条件 |
| 明确双方权责与经济关系 | 蒙特威与潜势分别投入什么、掌握什么权限、承担什么责任，收益如何形成？ | 分工、授权、费用承担及成果归属待决表 |
| 检查交付和售后能力 | 获得询盘之后，谁提供技术支持、报价、寄样、签约、发货和处理异常？ | 从线索到回款的责任闭环 |

其中最需要补上的，是**把每项主要投入与一个待验证的经营判断对应起来**。例如，招聘内容人员之前，要先明确内容服务哪类客户、提供什么信息、把咨询交给谁，以及用什么证据判断内容有效。

### 2 他们会从哪些原始素材入手？

已有方案用于寻找线索和历史决定；经营判断应尽可能回到原始记录。

| 原始素材 | 重点核查 | 能支持的判断 |
|---|---|---|
| 原料规格书、批次COA、检测方法及适用范围 | 牌号、批次、指标是否对应，检测能否支持拟用主张 | 实际可以向客户介绍什么 |
| 生产、库存和供货记录 | 可供数量、批次稳定性、交期、MOQ及异常情况 | 能否承接目标客户需求 |
| 有效报价、合同、订单、发票及回款记录 | 价格对应的规格、税运条件、账期、退换货与实际收入 | 业务如何成交、收益怎样形成 |
| 客户原始询盘、沟通记录、试样反馈和流失原因 | 客户使用场景、选择标准、替代产品、技术问题和采购障碍 | 优先服务谁、解决什么问题 |

### 3 他们会使用什么具体方法和工具？

方法应对应具体问题，工具负责记录、计算和验证，不用框架数量体现专业程度。

| 工作问题 | 具体方法 | 工具与输出 |
|---|---|---|
| 现有结论是否可信 | 建立「结论—来源—适用对象—资料日期—限制—核验状态」对应关系 | 证据台账；保留原文件、页码或工作表位置 |
| 哪类客户应优先开发 | 按需求强度、产品适配、验证难度、成交周期、交付能力及回款条件逐项比较；缺数据不强行评分 | 客户分群与优先级比较表 |
| 客户为什么买、为什么不买 | 结构化需求访谈、历史询盘复盘、试样反馈分析；避免只问「是否感兴趣」 | 访谈提纲、原始记录、异议与采购条件清单 |
| 业务路径是否完整 | 绘制从触达到回款的流程，逐步检查进入条件、退出条件及责任交接 | 业务流程图、线索台账、职责表 |
| 目标是否可达 | 从期末目标倒推新增、转化、退出及维护工作量；区分观测值与假设 | 可追溯的目标测算表和情景分析 |
| 团队需要多少人 | 任务数量×单次工时，加上存量维护、审核和协调时间，再与净可用工时比较 | 岗位工作量模型、兼岗冲突表 |
| 业务是否值得投入 | 分主体核算收入、成本和现金时点，再检查合并口径，避免重复计算内部支付 | 复用现有四方经营与现金模型 |
| 哪些假设最影响结果 | 敏感性分析与压力情景，检查开发延期、转化不足、合作流失和资金延迟 | 关键假设清单及应对措施 |
| 怎样用较小投入获得有效判断 | 事前确定验证问题、对象、方法、证据和通过条件，再安排试点 | 验证任务书、结果记录、阶段决策表 |
| 方案与PPT是否一致 | 对目标、岗位、预算、节点和决策事项进行交叉核对 | 一套基础数据，多种呈现，独立QA记录 |

具体工具可采用：

- **Excel或现有经营工作簿**：目标、工时、成本和现金测算，保留公式、单位与参数来源。
- **本地文档与资料台账**：保存原件、版本和结论出处。
- **官方数据库、企业官网及公开检索工具**：补充现行资质、标准和市场信息；公开检索不能替代企业原件。
- **适用的Word、PPT制作与渲染工具**：完成可编辑成果及版式检查。

客户访谈、询价、后台接入等尚未获授权的事项，先完成可审阅的执行准备，不将其写成已经开展。

### 4 除了你我，还有什么能证明结果正确？

需要把「正确」拆开。文件内容一致、计算正确、企业同意和市场有效，是四种不同的检验。

| 要验证的内容 | 可作为独立检验的证据 | 不能替代它的东西 |
|---|---|---|
| 产品事实是否真实 | 对应牌号与批次的资料、适用检测记录及技术质量复核 | 企业介绍、通用技术文献、营销文案 |
| 市场需求是否存在 | 目标客户的具体需求、采购条件、试样行为和后续推进记录 | 点赞、浏览、泛泛表示感兴趣 |
| 客户是否愿意交易 | 有条件的报价反馈、采购流程进展、订单、履约及回款记录 | 意向名单或免费领取样品 |
| 团队能否执行 | 实际任务演练、时间记录、交付质量及承接能力 | 岗位说明书或计划招聘人数 |
